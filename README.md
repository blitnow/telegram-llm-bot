# Telegram LLM Bot

Бот для групп, супергрупп и личных сообщений Telegram. Отвечает на текстовые вопросы через LLM API. Каждый диалог выбирается цепочкой reply; разные вопросы и ответвления сохраняют отдельный контекст. Подходит для Ubuntu 24.04 с 1 vCPU и 2 ГБ RAM при небольшой нагрузке, в том числе для сервера с работающим VPN.

Служба настроена для совместного использования VPS: не более 20% одного CPU, мягкий порог памяти 192 МБ, жёсткий лимит 256 МБ и пониженный приоритет CPU (`Nice=10`). Это ограничения потребления, а не постоянно зарезервированные ресурсы. При превышении лимита памяти служба может быть завершена и автоматически перезапущена. LLM выполняется у внешнего API-провайдера; модель на VPS не загружается. VPN всё равно может давать пики нагрузки, поэтому после установки проверьте память и работу VPN под обычной нагрузкой. Ограничения systemd действуют на службу бота; установка пакетов через apt/pip выполняется отдельно.

## Как общаться

| Сообщение | Контекст |
| --- | --- |
| `@имя_бота вопрос` без reply | Новый отдельный диалог |
| Reply на чужое сообщение + `@имя_бота, это правда?` | Текст исходного сообщения и новый вопрос |
| Reply на ответ бота | Вся сохранённая ветка до этого ответа и новое уточнение; тег необязателен |
| Reply на более ранний ответ бота | Ответвление от выбранного ответа; более поздние и соседние ответы не включаются |
| `/new@имя_бота вопрос` | Новый диалог, даже если сообщение отправлено через reply |
| `/help@имя_бота` | Справка |

В личке упоминание необязательно. Каждый вопрос без reply начинает новый диалог и там. В группе любой участник может продолжить общую ветку. Reply на сохранённый вопрос пользователя с упоминанием бота тоже продолжает соответствующий диалог. Для самостоятельного анализа того же сообщения используйте `/new@имя_бота` и включите нужный текст в вопрос.

SQLite сохраняет сообщения диалогов и связи между ними после перезапуска. История удаляется через 30 дней **после последнего успешного ответа в диалоге**, срок настраивается. Очистка выполняется при запуске и каждый час. Обычная переписка не сохраняется в историю. Если старая ветка уже удалена, бот сообщает об этом.

Каждая часть длинного ответа связана с полным ответом: уточнение можно отправить reply на любую часть. Контекст передаётся целиком до настроенного лимита; бот не обрезает его молча, а предлагает начать новый вопрос. Поддерживаются текст и подписи к вложениям. Изображения, документы, аудио, содержимое ссылок и reply из другого чата автоматически не читаются.

## Достоверность и системный промпт

В каждый запрос первым сообщением с ролью `system` добавляется [системный промпт](tg_llm_bot/system_prompt.txt). Он задаёт приоритет первичных источников, систематических обзоров и качественных исследований; требует различать факты, гипотезы и мнения; запрещает выдуманные исследования, DOI, цитаты и ссылки. Цитируемый текст рассматривается как данные, а не как инструкция.

Промпт не показывается в Telegram и не содержит ключей. Его текст доступен в исходниках публичного репозитория; это инструкция модели, а не секрет и не гарантия защиты от извлечения через запросы. LLM всё равно может ошибаться. Низкая температура и системные правила уменьшают риск, но не гарантируют достоверность.

**По умолчанию интернет-поиск выключен.** Бот отвечает по знаниям модели и тексту выбранной ветки. Каждому ответу добавляется честная пометка, что интернет-проверка не выполнялась. Одного промпта недостаточно, чтобы модель проверяла свежие факты или содержимое веб-страниц.

При желании можно включить платный поиск OpenRouter: см. ниже. Тогда бот отдельно выводит источники из `url_citation` аннотаций API. Если API не вернул ссылки, бот прямо сообщает, что проверка не подтверждена. Наличие ссылки само по себе не доказывает конкретное утверждение.

## 1. Создать Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте название и username, заканчивающийся на `bot`.
3. Сохраните выданный токен; он понадобится при установке.
4. Отправьте `/setjoingroups`, выберите бота и разрешите добавление в группы.
5. Отправьте `/setprivacy`, выберите бота и нажмите **Disable**. Это нужно для обычного `@упоминания` и вопросов через reply на чужое сообщение.
6. Если бот уже был в группе при изменении Privacy Mode, удалите его из группы и добавьте снова.

Боту не нужны права администратора для работы. Ему нужно разрешение отправлять сообщения. При выключенном Privacy Mode Telegram доставляет ему обычную переписку, однако приложение обрабатывает только обращения к боту. Правила доставки описаны в [Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get) и [Privacy Mode](https://core.telegram.org/bots/features#privacy-mode).

## 2. Получить LLM API-ключ

1. Зарегистрируйтесь на [OpenRouter](https://openrouter.ai/).
2. Создайте ключ на странице [API Keys](https://openrouter.ai/settings/keys).
3. При установке оставьте модель `openrouter/free`: это маршрутизатор между доступными бесплатными моделями. Он не гарантирует конкретную модель Qwen или DeepSeek.
4. Если хотите определённую модель, выберите её в [каталоге бесплатных моделей](https://openrouter.ai/models?max_price=0) и скопируйте её точный API ID с суффиксом `:free`.

Бесплатные модели могут быть перегружены или исчезать из каталога. Список и условия меняются: проверьте [лимиты OpenRouter](https://openrouter.ai/docs/api-reference/limits) перед использованием. На момент подготовки проекта базовый бесплатный лимит — 50 запросов в сутки и 20 в минуту; после покупки не менее $10 кредитов — 1000 в сутки при том же минутном лимите. Лимиты общие для ключа/аккаунта и могут расходоваться другими приложениями.

В боте по умолчанию установлены дополнительные общие лимиты: **45 запросов в сутки**, 18 в минуту, 1 одновременно и пауза 5 секунд между запросами одного пользователя в одном чате. Если бот уже отвечает, новое обращение получает просьбу повторить вопрос позже. Запрос с ошибкой API тоже считается попыткой. Счётчики сохраняются после перезапуска; день начинается в 00:00 UTC (03:00 МСК). Платные модели и поиск запрещены настройкой `allow_paid_models=false`. Для других API-провайдеров включение `allow_paid_models` означает, что стоимость нужно проверить самостоятельно.

## 3. Установить на VPS Ubuntu 24.04

Подключитесь к VPS по SSH; IP и пользователя возьмите в панели провайдера:

```bash
ssh root@IP_ВАШЕГО_VPS
```

Если входите обычным пользователем, команды с установкой выполняйте через `sudo`.

Скачайте проект после публикации репозитория:

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/blitnow/telegram-llm-bot.git
cd telegram-llm-bot
sudo bash scripts/install.sh
```

Если используете ZIP-архив, загрузите его на сервер, распакуйте, перейдите в папку проекта и выполните ту же команду `sudo bash scripts/install.sh`.

Скрипт запросит:

- токен Telegram-бота — ввод скрыт;
- API-ключ LLM — ввод скрыт;
- ID модели — Enter оставляет `openrouter/free`.

Скрипт установит Python 3.12, виртуальное окружение и зависимости, создаст отдельного служебного пользователя и включит службу `telegram-llm-bot`. Запуск происходит после проверки Telegram-токена и готовности polling. При неудачном обновлении скрипт пытается восстановить предыдущую версию и конфигурацию. Для установки нужны права root/sudo и исходящий HTTPS-доступ к Ubuntu-репозиториям, PyPI, Telegram и LLM API. Домен, HTTPS-сертификат и открытый входящий порт для бота не нужны.

Проверка:

```bash
sudo systemctl status telegram-llm-bot
sudo journalctl -u telegram-llm-bot -n 50 --no-pager
free -h
sudo systemctl show telegram-llm-bot -p MemoryCurrent -p MemoryPeak -p MemoryMax -p CPUUsageNSec
```

Добавьте бота в группу и отправьте `@имя_бота привет`. Затем сделайте reply на его ответ с уточнением. Проверьте также reply на чужой текст с `@имя_бота, это правда?`.

Один Telegram-токен должен обслуживаться одним запущенным экземпляром. Не запускайте локальную копию одновременно с VPS.

## 4. Управление

```bash
# Смотреть журнал в реальном времени
sudo journalctl -u telegram-llm-bot -f

# Перезапустить, остановить или запустить
sudo systemctl restart telegram-llm-bot
sudo systemctl stop telegram-llm-bot
sudo systemctl start telegram-llm-bot

# Обновить код из репозитория и сохранить ключи, настройки и историю
cd ~/telegram-llm-bot
git pull --ff-only
sudo bash scripts/install.sh --update
```

Пути установки:

| Назначение | Путь |
| --- | --- |
| Закрытая конфигурация и ключи | `/etc/telegram-llm-bot/config.json` |
| SQLite и память | `/var/lib/telegram-llm-bot/bot.sqlite3` |
| Версии приложения | `/opt/telegram-llm-bot/releases/` |
| Текущая версия | `/opt/telegram-llm-bot/current` |
| Служба | `/etc/systemd/system/telegram-llm-bot.service` |

У конфигурации права `0640`, владелец root, группа служебного пользователя. Данные закрыты правами каталога `0700`. Ключи и сообщения не выводятся в журналы приложения. Ключи никогда не передаются в LLM-промпте или аргументах команд.

Для смены ключей повторите обычную установку: пустой ввод сохраняет прежний ключ. Для изменения остальных параметров:

```bash
sudo nano /etc/telegram-llm-bot/config.json
cd /opt/telegram-llm-bot/current
sudo /opt/telegram-llm-bot/current/venv/bin/python -m tg_llm_bot --config /etc/telegram-llm-bot/config.json --check-config
sudo systemctl restart telegram-llm-bot
```

`allowed_chat_ids` по умолчанию пустой: бот работает в любых доступных ему чатах. Чтобы ограничить расход квоты, укажите разрешённые числовые ID, например `[-1001234567890, 123456789]`, включая ID личного чата, если он нужен. `system_prompt_path` позволяет задать путь к вашему UTF-8 файлу промпта; для VPS удобно `/etc/telegram-llm-bot/system_prompt.txt` с владельцем `root:telegram-llm-bot` и правами `0640`. Пустое значение использует встроенный промпт. Относительные пути отсчитываются от папки файла конфигурации.

История выбранного диалога и процитированное сообщение передаются OpenRouter и выбранному LLM-провайдеру. Учитывайте это при обсуждении личных или закрытых данных. После удаления локальной истории копии у API-провайдера регулируются его собственной политикой хранения.

Чтобы очистить всю локальную память, остановите службу и удалите базу вместе с файлами WAL/SHM:

```bash
sudo systemctl stop telegram-llm-bot
sudo rm -f /var/lib/telegram-llm-bot/bot.sqlite3 /var/lib/telegram-llm-bot/bot.sqlite3-wal /var/lib/telegram-llm-bot/bot.sqlite3-shm
sudo systemctl start telegram-llm-bot
```

Это также сбросит локальные счётчики и offset; квота OpenRouter от этого не восстановится. Telegram может повторно доставить ещё не подтверждённые обновления.

Для резервной копии SQLite сначала остановите службу, скопируйте весь каталог данных в защищённое место и затем запустите её. Конфигурация с ключами требует отдельного защищённого резервного копирования. Старые версии в `releases/` сохраняются для отката и со временем занимают место; удаляйте только версии, на которые не указывает `current`.

## Необязательный платный веб-поиск

На VPS измените два поля конфигурации:

```json
{
  "allow_paid_models": true,
  "web_search_enabled": true
}
```

Это фрагмент: измените соответствующие поля полного файла, остальные сохраните. Модель можно оставить бесплатной. После этого проверьте конфигурацию и перезапустите службу.

Веб-поиск OpenRouter **оплачивается отдельно даже с бесплатной моделью**, требует доступного баланса/квоты поиска и не гарантирует качество каждого результата. Перед включением прочитайте [условия и цены поиска](https://openrouter.ai/docs/guides/features/plugins/web-search). Бот отправляет плагин `web` только при явно включённой настройке. Без неё нет ни поиска, ни автоматического перехода на платную модель.

## Если не работает

- **В группе нет реакции:** проверьте username, `/setprivacy → Disable`, повторное добавление бота и право отправлять сообщения. Бот отвечает на отправленные сообщения, а не на ещё не отправленный текст в поле ввода.
- **401:** неверный или отозванный Telegram/LLM токен; замените его через повторную установку.
- **429:** квота или перегрузка API. Дождитесь восстановления либо выберите другую бесплатную модель.
- **402:** провайдер сообщил о недостатке квоты/баланса; проверьте аккаунт и настройки поиска.
- **404:** модель удалена из каталога или неверен `llm_base_url`; обновите настройки.
- **409 / служба перезапускается:** проверьте второй экземпляр бота и старый webhook. Если переходите на этот бот с webhook, сначала остановите прежнюю программу, затем удалите webhook командой ниже.
- **История недоступна:** срок хранения истёк, база удалена либо reply сделан на справку/ошибку. Начните новый вопрос или выберите другой ответ бота.
- **Диалог слишком длинный:** начните новую ветку и кратко передайте нужные факты. `max_context_chars` включает системный промпт и всю ветку; это лимит символов приложения, он не заменяет токенный лимит конкретной модели.

Удаление старого webhook без сброса ожидающих обновлений:

```bash
sudo systemctl stop telegram-llm-bot
cd /opt/telegram-llm-bot/current
sudo venv/bin/python -m tg_llm_bot --config /etc/telegram-llm-bot/config.json --remove-webhook
sudo systemctl reset-failed telegram-llm-bot
sudo systemctl start telegram-llm-bot
```

Доставка обновлений Telegram допускает повторные попытки. Сохранённые успешные запросы распознаются по ID и повторно не отправляются в LLM. При аварийном выключении ровно во время API-вызова или отправки ответа возможны повторный расход квоты либо частично доставленный ответ; строгая гарантия однократной обработки не заявляется.

## Локальная разработка и проверка

Требуется Python 3.12+:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp config.example.json config.json
chmod 600 config.json
```

Заполните ключи в `config.json`, затем:

```bash
.venv/bin/python -m tg_llm_bot --check-config
.venv/bin/python -m tg_llm_bot
```

Переменные `TELEGRAM_BOT_TOKEN` и `LLM_API_KEY` при наличии переопределяют ключи из JSON. Установочный скрипт поддерживает `--non-interactive` с этими переменными и необязательными `LLM_MODEL`, `LLM_BASE_URL`. Передавайте секреты через защищённое окружение/секрет-хранилище, избегая буквальных ключей в истории shell. Обычная интерактивная установка проще и безопаснее для первого запуска.

Тесты работают без реальных ключей, сетевых запросов и расхода квоты:

```bash
.venv/bin/python -m unittest discover -s tests -v
bash -n scripts/install.sh
```

Проверяются ветки и ответвления, перезапуск, разделение чатов и тем, цитируемые сообщения, длинные ответы с emoji, лимиты, ошибки API, бесплатный режим и скрытие секретов в ошибках.

Отдельная проверка установщика в **одноразовом** Docker-контейнере Ubuntu 24.04:

```bash
docker run --rm --memory=768m --cpus=1 -v "$PWD:/project:ro" ubuntu:24.04 bash /project/tests/deployment_smoke.sh
```

Она проверяет реальную установку Python-зависимостей, права служебного пользователя, корректность systemd unit, обновление с сохранением базы и откат после ошибки. Операции запуска службы имитируются, поскольку обычный контейнер не запускает systemd как PID 1. Реальные Telegram и LLM API здесь не вызываются.

Если репозиторий ещё не опубликован, создайте пустой публичный `blitnow/telegram-llm-bot` и выполните в папке проекта:

```bash
git add README.md pyproject.toml requirements.in requirements.txt config.example.json tg_llm_bot scripts deploy tests .gitignore .github LICENSE
git commit -m "Add Telegram LLM bot with reply-based conversations"
git branch -M main

git push -u origin main
```

Используйте GitHub CLI/credential manager или SSH-ключ для авторизации. Не помещайте access token в URL remote. `config.json`, окружения, базы и локальные секреты исключены через `.gitignore`; перед публикацией проверьте `git diff --cached`.
